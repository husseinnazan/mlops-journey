# Databases, SQL & Relational Databases — A Beginner's Notebook

This notebook explains databases, SQL, and relational databases from scratch, using one running example all the way through: a tiny bookstore database with authors, books, and genres.

Every code block uses the `sqlite3` command-line tool, except the last section, which shows how to talk to the same database from Python.

## 1. What is a Database?

A database is just an organized place to store data so it can be saved, searched, and updated reliably — instead of scattering information across random text files or spreadsheets.

Think of it like a digital filing cabinet:

- A filing cabinet = the database
- Drawers = tables (e.g. "Authors", "Books")
- Folders in a drawer = rows (one folder = one author, one book)
- Labels on each folder (name, date, ID) = columns

A **Database Management System (DBMS)** is the software that lets you create, read, update, and delete data in that cabinet — safely and quickly. Examples: SQLite, PostgreSQL, MySQL, SQL Server.

We'll use SQLite in this notebook because it needs no server setup — it's just a single file on disk, perfect for learning.

## 2. What is SQL?

SQL (Structured Query Language) is the language you use to talk to a database. With SQL you can:

| Action | SQL Keyword |
|---|---|
| Create structure | `CREATE TABLE` |
| Add data | `INSERT` |
| Read data | `SELECT` |
| Change data | `UPDATE` |
| Remove data | `DELETE` |

SQL reads almost like plain English:

```sql
SELECT title FROM books WHERE published_year > 2000;
```

This means: "Give me the title from the books table, but only where published_year is greater than 2000."

## 3. What is a Relational Database?

A relational database organizes data into tables (like spreadsheets) that can be linked to each other through shared values called keys.

**Key vocabulary:**

- **Table** — a collection of similar things (e.g. authors, books)
- **Row** (a.k.a. record) — one single item in a table (e.g. one specific book)
- **Column** (a.k.a. field) — one property of that item (e.g. title, price)
- **Primary Key (PK)** — a column that uniquely identifies each row (like an ID number). No two rows share the same primary key.
- **Foreign Key (FK)** — a column in one table that points to the primary key of another table. This is how tables get related to each other.

Why split data into multiple tables instead of one giant table? Because it avoids repeating the same information over and over (e.g. writing "J.K. Rowling" next to every single one of her books), and it keeps data consistent — update the author once, and every linked book reflects it.

We'll build exactly this: an `authors` table and a `books` table, linked by a foreign key.

## 4. Setting Up SQLite

Open your terminal. SQLite comes with a small command-line tool called `sqlite3`.

Create (or open) a database file called `bookstore.db`:

```bash
sqlite3 bookstore.db
```

This drops you into an interactive SQLite prompt (`sqlite>`). From here on, every SQL statement in this notebook can be typed directly at that prompt, or run non-interactively like this from your normal terminal:

```bash
sqlite3 bookstore.db "SELECT 'hello, database!';"
```

A few handy SQLite-only commands (note: no semicolon needed, and they start with a dot):

```bash
sqlite3 bookstore.db ".tables"      # list all tables
sqlite3 bookstore.db ".schema"      # show table structures
```

## 5. Creating Our First Table

Let's create the `authors` table. Every author has an `id` (primary key), a `name`, and a `country`.

```bash
sqlite3 bookstore.db "
CREATE TABLE authors (
    id      INTEGER PRIMARY KEY,
    name    TEXT NOT NULL,
    country TEXT
);
"
```

Breaking this down:

- `id INTEGER PRIMARY KEY` — a unique number identifying each author, auto-generated by SQLite if you don't supply one.
- `name TEXT NOT NULL` — a text field that cannot be left empty.
- `country TEXT` — an optional text field.

Check it was created:

```bash
sqlite3 bookstore.db ".schema authors"
```

## 6. Inserting Data

Let's add a couple of authors:

```bash
sqlite3 bookstore.db "
INSERT INTO authors (name, country) VALUES ('George Orwell', 'UK');
INSERT INTO authors (name, country) VALUES ('Naguib Mahfouz', 'Egypt');
INSERT INTO authors (name, country) VALUES ('Haruki Murakami', 'Japan');
"
```

We didn't specify `id` — SQLite assigned 1, 2, and 3 automatically.

## 7. Reading Data with SELECT

Get everything from the table:

```bash
sqlite3 bookstore.db "SELECT * FROM authors;"
```

`*` means "all columns." To make output readable in the terminal, turn on headers and column mode:

```bash
sqlite3 -header -column bookstore.db "SELECT * FROM authors;"
```

Select specific columns:

```bash
sqlite3 -header -column bookstore.db "SELECT name, country FROM authors;"
```

Filter rows with `WHERE`:

```bash
sqlite3 -header -column bookstore.db "SELECT * FROM authors WHERE country = 'Japan';"
```

Sort results with `ORDER BY`:

```bash
sqlite3 -header -column bookstore.db "SELECT * FROM authors ORDER BY name ASC;"
```

## 8. Updating and Deleting Data

Fix a typo — say Orwell's country should be more specific:

```bash
sqlite3 bookstore.db "
UPDATE authors SET country = 'England' WHERE name = 'George Orwell';
"
```

**Always use `WHERE` with `UPDATE` and `DELETE`** — without it, you'll update or delete every row in the table.

Delete a row (example only — don't run this if you want to keep all three authors):

```bash
sqlite3 bookstore.db "DELETE FROM authors WHERE name = 'Placeholder Author';"
```

Confirm nothing was accidentally lost:

```bash
sqlite3 -header -column bookstore.db "SELECT * FROM authors;"
```

## 9. Linking Tables: Foreign Keys & the books Table

Now let's create the `books` table, which relates to `authors` through a foreign key.

```bash
sqlite3 bookstore.db "
PRAGMA foreign_keys = ON;

CREATE TABLE books (
    id              INTEGER PRIMARY KEY,
    title           TEXT NOT NULL,
    published_year  INTEGER,
    author_id       INTEGER,
    FOREIGN KEY (author_id) REFERENCES authors(id)
);
"
```

`author_id` doesn't store the author's name — it stores the author's `id`. This is the relational link: instead of duplicating "George Orwell" in every row, we just point to author 1.

Insert some books:

```bash
sqlite3 bookstore.db "
INSERT INTO books (title, published_year, author_id) VALUES ('1984', 1949, 1);
INSERT INTO books (title, published_year, author_id) VALUES ('Animal Farm', 1945, 1);
INSERT INTO books (title, published_year, author_id) VALUES ('Palace Walk', 1956, 2);
INSERT INTO books (title, published_year, author_id) VALUES ('Norwegian Wood', 1987, 3);
"
```

Note that author 1 (Orwell) has two books here. This is a **one-to-many relationship**: one author can have many books, but each book has only one author.

## 10. Combining Tables with JOIN

This is the payoff of relational design. A `JOIN` lets you pull matching rows from two related tables into one result.

```bash
sqlite3 -header -column bookstore.db "
SELECT books.title, books.published_year, authors.name AS author
FROM books
JOIN authors ON books.author_id = authors.id;
"
```

This says: "For every book, look up its `author_id` in the `authors` table and grab that author's name." You get readable results like:

```
title           published_year  author
--------------  ---------------  ---------------
1984            1949             George Orwell
Animal Farm     1945             George Orwell
Palace Walk     1956             Naguib Mahfouz
Norwegian Wood  1987             Haruki Murakami
```

Add a `WHERE` to a join, e.g. only Orwell's books:

```bash
sqlite3 -header -column bookstore.db "
SELECT books.title, books.published_year
FROM books
JOIN authors ON books.author_id = authors.id
WHERE authors.name = 'George Orwell';
"
```

## 11. A Many-to-Many Relationship: Genres

So far: one author → many books (one-to-many). But what about genres? A book can belong to multiple genres (e.g. "1984" is both Dystopian and Political Fiction), and a genre can apply to many books. That's a **many-to-many relationship**, and it needs a third table — a **junction table** — in the middle.

```bash
sqlite3 bookstore.db "
CREATE TABLE genres (
    id   INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE book_genres (
    book_id  INTEGER,
    genre_id INTEGER,
    FOREIGN KEY (book_id) REFERENCES books(id),
    FOREIGN KEY (genre_id) REFERENCES genres(id),
    PRIMARY KEY (book_id, genre_id)
);
"
```

`book_genres` has no data of its own — it just stores pairs of IDs, linking a book to a genre.

Add some genres and connect them to books:

```bash
sqlite3 bookstore.db "
INSERT INTO genres (name) VALUES ('Dystopian');
INSERT INTO genres (name) VALUES ('Political Fiction');
INSERT INTO genres (name) VALUES ('Literary Fiction');

INSERT INTO book_genres (book_id, genre_id) VALUES (1, 1); -- 1984 -> Dystopian
INSERT INTO book_genres (book_id, genre_id) VALUES (1, 2); -- 1984 -> Political Fiction
INSERT INTO book_genres (book_id, genre_id) VALUES (2, 2); -- Animal Farm -> Political Fiction
INSERT INTO book_genres (book_id, genre_id) VALUES (4, 3); -- Norwegian Wood -> Literary Fiction
"
```

Now find every genre attached to "1984" by joining across three tables:

```bash
sqlite3 -header -column bookstore.db "
SELECT books.title, genres.name AS genre
FROM books
JOIN book_genres ON books.id = book_genres.book_id
JOIN genres ON genres.id = book_genres.genre_id
WHERE books.title = '1984';
"
```

## 12. Aggregate Functions: Counting and Grouping

SQL can summarize data, not just list it. `COUNT()` counts rows, and `GROUP BY` buckets rows before counting.

How many books does each author have?

```bash
sqlite3 -header -column bookstore.db "
SELECT authors.name, COUNT(books.id) AS total_books
FROM authors
JOIN books ON books.author_id = authors.id
GROUP BY authors.name;
"
```

Other useful aggregates: `SUM()`, `AVG()`, `MIN()`, `MAX()`. Example — the average publication year across all books:

```bash
sqlite3 bookstore.db "SELECT AVG(published_year) FROM books;"
```

## 13. Quick Recap

- A database stores organized data; a DBMS (like SQLite) manages it.
- SQL is the language for creating, reading, updating, and deleting data.
- A relational database splits data into tables linked by primary keys and foreign keys, avoiding duplication.
- `JOIN` reassembles related data from multiple tables into one result.
- A junction table handles many-to-many relationships.
- `GROUP BY` + aggregate functions summarize data.

Our final `bookstore.db` now contains four linked tables: `authors`, `books`, `genres`, and `book_genres`.

## 14. Using SQLite from Python

Everything above can also be done through Python's built-in `sqlite3` module — no extra installation needed. This connects to the exact same `bookstore.db` file we've been building.

```python
import sqlite3

# Connect to the same database file we built above
connection = sqlite3.connect("bookstore.db")
cursor = connection.cursor()

# Run a query joining books and authors
cursor.execute("""
    SELECT books.title, books.published_year, authors.name
    FROM books
    JOIN authors ON books.author_id = authors.id
    ORDER BY books.published_year
""")

# Fetch and print all matching rows
for title, year, author in cursor.fetchall():
    print(f"{year} — {title} by {author}")

# Insert a new book using placeholders (safe from SQL injection)
cursor.execute(
    "INSERT INTO books (title, published_year, author_id) VALUES (?, ?, ?)",
    ("Kafka on the Shore", 2002, 3)
)
connection.commit()  # save changes to the file

connection.close()
```

Key ideas:

- `sqlite3.connect("bookstore.db")` opens the same file the `sqlite3` CLI was using — Python and the command line share the same data.
- A **cursor** is what you use to execute SQL and fetch results.
- Always use `?` placeholders (not string formatting) when inserting variable values — it keeps your queries safe and correct.
- `connection.commit()` is required to actually save `INSERT`/`UPDATE`/`DELETE` changes to disk.

That's the full loop: design tables, relate them with keys, query with SQL from the terminal, and use that same database from a real program.
